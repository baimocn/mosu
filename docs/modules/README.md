# 洞察模块

四个模块的职责边界、数据结构、接口契约与已知问题。面向要接入这些接口或排查数据
疑问的人。

| 文档 | 主题 | 回答什么问题 |
|------|------|------------|
| [数据统计](stats.md) | 全库计数、构成、时间分布、高频词 | 库里有多少、什么构成、什么时候聊 |
| [画像](profile.md) | 本人 / 联系人画像 | 我（或 TA）是个什么样的人 |
| [年报](report.md) | 自然年汇总 | 这一年聊了多少、和谁、聊什么 |
| [联系人](contacts.md) | 通讯录名单 + 单人往来明细 | 我有哪些往来对象、和某人之间发生了什么 |

## 边界

四个模块共用 `core/analytics.py`（计数聚合）与 `core/profile.py`（语义蒸馏），
共享同一把全局 `_ds_lock`。分工是清晰的：

- **数据统计**只做计数与 `GROUP BY`，不解压消息正文，秒级返回
- **画像**会逐条解压、做分词与情感打分，慢一个数量级
- **年报**介于两者之间，除关键词外不逐条解码
- **联系人**是名单查询 + 复用统计层的单会话聚合

## 共享的数据基础

**分片**：消息散落在 `message/message_0.db`、`message_1.db`…，同一会话的表会同时
存在于多个分片，聚合在 Python 内存里完成。

**消息类型**：先由 `local_type` 经 `KIND_BY_TYPE` 映射为 7 种
（`text/image/voice/video/emoji/file/system`），未命中为 `other`。注意
`T_APPMSG(49)` 整体映射为 `file`——链接、引用、小程序、转账都归入「文件」。

**锁**：所有洞察接口全程持 `_ds_lock`（全局 `RLock`），重操作期间其他数据 API
一律阻塞。轻量的关键词扫描走 `TaskHub` 异步，最重的画像与年报却是同步 GET。

**异步任务**：`POST` 类接口返回 `{"taskId": "..."}`，轮询
`GET /api/task?id=<taskId>` 取 `{id, kind, status, cost, result, error}`。
**字段名是 `taskId`**，不是 `id`。

## 已修（本轮）

审查中发现并已修复、且加了不变量测试锁住的：

- 高频词任务字段名不一致（`taskId` vs `d.id`）导致功能静默失效
- 画像星期下标错位一天（`%w` 的 0 是周日）
- `/api/contact` 子串兜底可能命中另一个人
- `social` 以 displayName 为键导致同名会话被合并
- `insights` 声称「周末高于工作日」但从未计算
- `questionRate` 只统计半角 `?`，全角 `？` 全漏
- 采样取到每个会话**最早** N 条而非最近 N 条
- 凌晨窗口标注为 0-6 点（实为 0-5），早间窗口与凌晨重叠
- 空库时 `render_markdown` 对 `peakHour=None` 格式化崩溃
