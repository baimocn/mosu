# 密钥自动获取（keyfinder）

墨溯能在一台**全新电脑**上自动拿到数据库密钥：只要微信 PC 4.x 在运行且已登录，
点一下按钮（或 `mosu key find`）即可，无需注入、无需 hook、无需其他工具。

## 用法

```bash
python cli/mosu.py key find            # 自动获取并写入密钥库
python cli/mosu.py key find --no-save  # 只看不写
```

GUI 首启向导里点「开始自动获取」走同一条链路，带实时进度（SSE）。

## 原理（本机微信 4.1.15.13 实测，还原出的密钥与 HMAC 权威校验逐字节一致）

1. **掩码是静态常量**：微信把数据库口令交给 WCDB 前，会用一段 32 字节常量做 XOR。
   这段常量以 4 条 `mov rdx, imm64` + `test rax, rax` 的指令序列出现在
   `Weixin.dll` 的代码段里，可以零依赖解析 PE 直接提取。
2. **口令以 XOR 形态留在堆上**：对象结构稳定——
   `[6 字节指针][10 字节 0][长度=32][标记 0x2f]`。按结构定位、解指针、读 32 字节。
3. **XOR 还原 + 权威校验**：候选 XOR 掩码还原成口令，对目标库第一页做
   PBKDF2-HMAC-SHA512（256000 轮）校验，通过即确认。校验是并行的
   （hashlib 释放 GIL，8 线程约 4 倍速），本机 2800 候选约 30 秒内命中。

## 为什么直接搜明文搜不到

微信 4.0.3.36+ 不再在内存里保留 `x'64hex'` 明文口令（老一代工具全部失效的原因）。
口令只以「XOR 后的原始字节」形态短暂存在于 WCDB 的 Cipher 配置对象里。

## 安全边界（先说清楚，再谈信任）

- 只调用 `ReadProcessMemory` **只读**内存，不写、不注入 DLL、不挂调试器、
  不改微信任何文件、不联网。
- 校验通过才写入密钥库；写不进也会把密钥返回给界面，由你决定。
- 仅用于备份与分析**你自己登录账号**的数据。

## 已知边界与降级

| 情况 | 表现 | 出路 |
|---|---|---|
| 微信没在运行 / 未登录 | 预检失败，明确提示 | 登录微信后重试 |
| 微信版本变化导致结构/签名变化 | 0 候选或校验全败 | 向导提供诊断摘要（不含密钥）可发给任意大模型分析；或手动填密钥 |
| 跨大版本升级换密钥 | 校验失败 | 重启微信重试；新版本内密钥不变 |
| 小号 / 几乎没数据的账号 | 候选里没有口令 | 社区实测小号口令不驻留内存，用主账号或手动填 |
