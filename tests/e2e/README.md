# 端到端测试（E2E）

真实浏览器驱动，覆盖全部 10 个页面。**不是接口测试**——接口全 200 但页面白屏的情况，
本项目真实发生过（`views-browse.js` 的 `M.mediaUrl` 崩溃）。

## 怎么跑

```bash
# 前置：GUI 服务必须在跑
python cli/mosu.py gui --port 8788

# 全量
python tests/e2e/run_e2e.py

# 只跑某个模块（--only 匹配函数名）
python tests/e2e/run_e2e.py --only browse
python tests/e2e/run_e2e.py --only search

# 有头模式：能看见浏览器在点（排查时用）
python tests/e2e/run_e2e.py --headed
```

退出码：`0` 全通过；`1` 有模块失败；`2` 服务没启动。

## 产物

```
.cache/e2e/<时间戳>/
  report.json      # 结构化结果：每个模块每步的 ok / detail / 截图名
  *.png            # 每步一张截图
```

`report.json` 里 `summary.failed_modules` 直接给出挂了哪几个模块。

## 每个模块测什么

| 模块 | 关键断言 |
|------|---------|
| 控制台 | 正文有内容、状态卡片、导航完整 |
| 数据浏览 | 会话列表、**点开会话出消息**（历史白屏点）、会话列表不消失<br>消息条数 ≥20、载入更早生效、深链 F5 后仍可用 |
| 全库搜索 | 导航进入即弹框、结果渲染、**首页结果 ≥20 条**（防"只返回 1 条也通过"）<br>显示命中数、下一页换内容、点结果跳转后出消息 |
| 数据统计 | 正文、svg 图表数量 |
| 画像 | 内容加载（约 5s）、卡片 ≥5、字段表 ≥5 |
| 年报 | 内容加载（约 5.6s） |
| 联系人 | 列表渲染 |
| 朋友圈 | 内容渲染、**对取不到的图有明确提示** |
| 导出 | 页面渲染、导出按钮存在（不真的生成文件） |
| 设置 | 页面渲染 |

## 三条设计原则（都是踩过坑总结的）

### 1. 轮询等待，绝不写死 sleep

各页加载差异极大：联系人 0.5s、画像 5.1s、年报 5.6s（全库聚合 23 万条）。
写死 `sleep(2)` 会把慢页面误判成"白屏"——第一版就这么误报了 4 个模块。

用的是 `wait_content(page, min_len=..., selector=...)`，达到条件立刻返回，
不必等到超时。**注意**：正文比 `min_len`，元素比 `min_count`，别搞混
（第一版写错了，导致阈值形同虚设）。

### 2. 断言"数量合理"，不能只断言"大于 0"

消融实验发现的：把搜索 `limit` 从 80 改成 1，只判 `>0` 的话 **10/10 全绿**——
测试看着通过、功能其实坏了。所以关键步骤都断言下界（气泡 ≥20、结果 ≥20）。

### 3. 每个模块独立 page

朋友圈有异步探测（`/api/moments/probe`），切页后才返回 404，
会串到下一个模块账上——导出模块曾被朋友圈的 29 个 404 冤判失败。

## 已知失败怎么处理

模块可以声明 `expected_failures: {url片段: 原因}`，框架把它单独记为
「已知失败（预期内）」并通过；**未声明**的才算缺陷。

这样既不掩盖问题，也不让数据层面的固有限制永远挡着验收。

当前已声明两项：

| 模块 | 前缀 | 原因 |
|------|------|------|
| 朋友圈 | `/api/remote` | 微信不把朋友圈图片落盘，腾讯图床又拒绝直连（400 / X-ErrNo:-106）。已核验：本机全盘按 md5 搜索 0 命中 |
| 数据浏览 | `/api/media` | 部分图片本地只有一个未下载的占位文件（几百字节）。实测 15992 张里 999 张属此类 |

## 消融实验（验证测试本身有效）

改代码看测试能不能抓到，是判断"测试是真的还是摆设"的唯一办法。
已做三轮：

| 注入的 bug | 结果 |
|-----------|------|
| `computed.M` 返回 `undefined`（复现历史白屏） | ✅ 抓到：`TypeError: Cannot read properties of undefined (reading 'mediaUrl')`，6 步挂 5 步 |
| 搜索 `limit` 改成 1 | ❌ **第一轮没抓到**（只判 >0）→ 补了"结果数 ≥20"断言后 ✅ 抓到 |
| 正常代码 | ✅ 10/10 通过、40/40 步通过 |

**建议每次改动核心逻辑后，至少跑一次对应的消融实验。**
一个从没抓到过 bug 的测试，不能证明它在工作。

## 局限（这些测不了）

- **导出**：只验证按钮存在，不真的生成文件（会产生大文件、耗时不可控）
- **语音播放**：无头浏览器不出声，只能验元素存在
- **MCP server**：是独立进程，不在 GUI 覆盖范围（有 `tests/test_mcp*.py`）
- **真实微信交互**：密钥获取、解密开库不在 E2E 范围
